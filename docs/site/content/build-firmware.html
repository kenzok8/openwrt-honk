自行编译固件

自己编译只要两件事：内核开 DEBUG_INFO_BTF，包选进固件一起编。这样出来就是完整的，不用再装 BTF 补丁包，也没有 kmod 版本对不上的问题。

先确认能编

自己编固件只适用 25.12（内核 6.12+）。24.10 的内核 6.6 带不动稳定通道的核心，那一边请直接用实验源的 .ipk，见安装与升级。

三步

# 1. feeds.conf.default 加两行
src-git honk https://github.com/kenzok8/openwrt-honk
src-git small https://github.com/kenzok8/small     # 提供 v2ray-geoip / v2ray-geosite

./scripts/feeds update -a
./scripts/feeds install -a -p honk
./scripts/feeds install -a -p small

# 2. make menuconfig
#   Network → Web Servers/Proxies → honk
#   LuCI → Applications → luci-app-honk
#   Kernel → 打开 CONFIG_DEBUG_INFO_BTF（关键，见下）

# 3. 编译
make -j$(nproc)

honk 与 luci-app-honk 都用 PKG_SOURCE 下载预编译好的核心与 Doona 归档，不需要 Rust、Zig、Node 工具链，只要能访问 GitHub Releases。

内核选项

缺了这些，honk 启动检查会直接拒绝（报 kernel_requirements_unmet）。数据面至少要：

CONFIG_BPF=y
CONFIG_BPF_SYSCALL=y
CONFIG_BPF_JIT=y
CONFIG_CGROUP_BPF=y
CONFIG_NET_SCHED=y
CONFIG_NET_CLS_ACT=y
CONFIG_NET_XGRESS=y
CONFIG_NET_NS=y

默认开启的首包保留 UDP 还要：

CONFIG_NF_TABLES=y|m
CONFIG_NF_TABLES_INET=y|m
CONFIG_NFT_CT=y|m
CONFIG_NFT_QUEUE=y|m
CONFIG_NETFILTER_NETLINK_QUEUE=y|m

BTF 是启动必需项，honk 加载 eBPF 时要拿它当目标描述。自己编固件最省事的做法是直接开内核 BTF：

CONFIG_DEBUG_INFO_BTF=y

不开也能跑，但要另外提供 BTF 文件（vmlinux-btf 包或 HONK_VMLINUX_BTF），多一层维护。

想要「原生 UDP 接收追踪」再补这两项，缺了只降级、不影响启动：

CONFIG_FUNCTION_TRACER=y
CONFIG_DYNAMIC_FTRACE=y
cgroup v2 与 CONFIG_CGROUP_BPF 是硬性要求。根 cgroup 的 sock_ops 槽位被旧程序占用也会导致启动失败。

bpffs 必须挂载

eBPF map 只能固定在 bpffs，普通目录不行。标准 OpenWrt 由 /etc/init.d/boot 自动挂载，自编或精简固件要确认：

grep " /sys/fs/bpf " /proc/mounts || mount -t bpf bpf /sys/fs/bpf

没能自动挂载的，写进 /etc/fstab 一劳永逸：

bpf /sys/fs/bpf bpf defaults 0 0

依赖谁来提供

依赖来源选 honk 时自动带上
kmod-sched-core · kmod-sched-bpf · kmod-veth · kmod-nft-queueOpenWrt 树内会，写在 honk 的 DEPENDS 里
ip-full · sqlite3-cli · coreutils-stat · ubus · jshn · usign · ca-bundle · jsonfilterOpenWrt 树内会
v2ray-geoip · v2ray-geositekenzok8/small 的 v2ray-geodata（kenzok8/wall 也有）不会，要加 feeds
vmlinux-btf—编译路径不需要，见下

为什么编译时不用碰 vmlinux-btf

vmlinux-btf 解决的是「固件已经刷好、内核没开 BTF」的情况，靠一个按内核版本编的包补上 BTF 文件。你自己编固件时把 DEBUG_INFO_BTF 打开，BTF 直接来自内核本身，这个包的存在就没意义了，也就不用追着内核版本找包。

编译时常见的坑

现象原因与处理
Makefile:N: /package.mk: No such file or directory$(INCLUDE_DIR) 为空，源码树被改过或在子目录里直接 make。在顶层目录重跑，必要时 make distclean
package/kernel/bpf-headers failed to build这个包由 dae/daed 一类 eBPF 包带进来，honk 不依赖它；同树里去掉那些包就能过
unable to select packages: kmod-xxx装包时报的，说明源里没有匹配当前内核的 kmod。编固件时选进去就不会遇到
用 ImageBuilder 出的固件装 kmod 失败ImageBuilder 不重编内核，kmod 只能拿官方源里的，内核一换就对不上

编完开机先验三行

uname -r                                        # 6.12+ 或 6.6.40+
ls -l /sys/kernel/btf/vmlinux                   # 有，说明 DEBUG_INFO_BTF 生效
lsmod | grep -E "sch_ingress|cls_bpf|veth|nft_queue"
grep " /sys/fs/bpf " /proc/mounts               # 有，说明 bpffs 已挂

四条都对，再到 LuCI「服务 → Honk → 维护 → 系统检查」过一遍，全部通过就能启动。
