自行编译固件

自己编固件时，honk 要的两个东西最容易漏：内核选项和依赖模块。这一页把它们列全，照着勾就能编译通过、开机就能起。

先选通道

你的固件用哪个内核要求
OpenWrt / ImmortalWrt 25.12稳定通道，.apkLinux 6.12+
OpenWrt / ImmortalWrt 24.10Linux 6.6 实验通道，.ipkLinux 6.6.40+

两条通道的包不通用，配置备份也不能互导。

把包编进固件

别「先编固件、再装 ipk」。把包选进 menuconfig 一起编，kmod 依赖会自动带上，和目标内核同源，永远不会出现「源里没有你这版内核的 kmod」。

# feeds.conf.default
src-git honk https://github.com/kenzok8/openwrt-honk
src-git wall https://github.com/kenzok8/wall                # v2ray-geoip / v2ray-geosite
src-git vmlinux-btf https://github.com/kenzok8/vmlinux-btf  # 内核没开 BTF 时才需要

./scripts/feeds update -a
./scripts/feeds install -a -p honk
./scripts/feeds install -a -p wall
./scripts/feeds install -a -p vmlinux-btf

make menuconfig
#   Network → Web Servers/Proxies → honk
#   LuCI → Applications → luci-app-honk

honk 与 luci-app-honk 都用 PKG_SOURCE 下载预编译好的核心与 Doona 归档，编译固件不需要 Rust、Zig、Node 工具链，只要能访问 GitHub Releases。

依赖谁来提供

依赖来源选 honk 时自动带上
kmod-sched-core · kmod-sched-bpf · kmod-veth · kmod-nft-queueOpenWrt 树内会，写在 honk 的 DEPENDS 里
ip-full · sqlite3-cli · coreutils-stat · ubus · jshn · usign · ca-bundle · jsonfilterOpenWrt 树内会
v2ray-geoip · v2ray-geositekenzok8/wall 的 v2ray-geodata不会，要加 feeds
vmlinux-btfkenzok8/vmlinux-btf不会，有意不设成依赖；内核开 DEBUG_INFO_BTF 则不需要

内核选项

缺了这些，honk 启动检查会直接拒绝（报 kernel_requirements_unmet）。数据面至少要：

CONFIG_BPF=y
CONFIG_BPF_SYSCALL=y
CONFIG_BPF_JIT=y
CONFIG_CGROUP_BPF=y
CONFIG_NET_SCHED=y
CONFIG_NET_CLS_ACT=y
CONFIG_NET_XGRESS=y
CONFIG_NET_NS=y

默认开启的首包保留 UDP 还要：

CONFIG_NF_TABLES=y|m
CONFIG_NF_TABLES_INET=y|m
CONFIG_NFT_CT=y|m
CONFIG_NFT_QUEUE=y|m
CONFIG_NETFILTER_NETLINK_QUEUE=y|m

这两项决定能不能少装一个补丁包：

CONFIG_DEBUG_INFO_BTF=y      # 内核自带 BTF，不用再装 vmlinux-btf
CONFIG_FUNCTION_TRACER=y
CONFIG_DYNAMIC_FTRACE=y      # 想要「原生 UDP 接收追踪」
cgroup v2 与 CONFIG_CGROUP_BPF 是硬性要求。根 cgroup 的 sock_ops 槽位被旧程序占用也会导致启动失败。

用户态依赖

选进固件即可，不用手工装：ca-bundle、ip-full、ubus、jsonfilter、jshn、sqlite3-cli、usign、coreutils-stat、v2ray-geoip、v2ray-geosite，以及 kmod-sched-core、kmod-sched-bpf、kmod-veth、kmod-nft-queue。

编译时常见的坑

现象原因与处理
Makefile:N: /package.mk: No such file or directory$(INCLUDE_DIR) 为空，源码树被改过或在子目录里直接 make。在顶层目录重跑，必要时 make distclean
package/kernel/bpf-headers failed to build这个包由 dae/daed 一类 eBPF 包带进来，honk 不依赖它；同树里去掉那些包就能过
unable to select packages: kmod-xxx装包时报的，说明你的源里没有匹配当前内核的 kmod。编固件时选进去就不会遇到
用 ImageBuilder 出的固件装 kmod 失败ImageBuilder 不重编内核，kmod 只能拿官方源里的，内核一换就对不上

编完开机先验三行

uname -r                                        # 6.12+ 或 6.6.40+
ls -l /sys/kernel/btf/vmlinux                   # 有 BTF 就不用装补丁包
lsmod | grep -E "sch_ingress|cls_bpf|veth|nft_queue"

三条都对，再到 LuCI「服务 → Honk → 维护 → 系统检查」过一遍，全部通过就能启动。
