Honk

Honk 是给 OpenWrt 用的透明代理一体包：一个基于 eBPF 的核心，配一套 LuCI 管理界面和一个自带的核心 Web 界面。流量在内核态分流，直连流量几乎不额外消耗 CPU。

只发 OpenWrt / ImmortalWrt 25.12（内核 6.12+）的 .apk。24.10 及更早的内核版本装上也起不来，安装脚本会先查内核再决定是否继续。
安装与升级 →一键脚本、软件源、卸载 内核与 BTF →起不来先看这一页 初始化与配置 →初始化、节点、Doona

三个组件

组件说明
honk基于 eBPF 的透明代理核心，dae 风格的 Rust 重写；常驻内存小，直连流量几乎零开销
luci-app-honkLuCI 管理界面：概览、配置（订阅 / 粘贴节点 / dae 导入）、日志、维护
Doona核心自带的 Web 界面，装到 /usr/share/doona，管理节点、分组、路由、DNS 与订阅，不另起服务

支持范围

架构状态
x86_64主力支持（软路由）
aarch64_cortex-a53 · aarch64_cortex-a72 · aarch64_cortex-a76 · aarch64_generic支持，ARM64 设备（含树莓派 5 这类 a76 设备）
arm_cortex-a7_neon-vfpv4 · arm_cortex-a9实验性：上游只发 x86_64 / aarch64，这两个是源码交叉编译，未做真机验证

它不是什么

  • 不是多内核面板。Honk 只有一个内核，不做 dae / sing-box / mihomo 切换。
  • 不是规则订阅转换器。分流规则写在 config.dae 里，或直接在 Doona 里调。
  • 不支持 24.10 及更早的固件 —— eBPF 数据面要 Linux 6.12+。

从哪里开始

没装过就先看安装与升级；装完起不来，直接跳内核与 BTF；能起来但不知道怎么配，看初始化与配置。
