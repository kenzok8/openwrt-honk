初始化与配置

装完包之后，服务默认是停的、也没初始化。顺序是：初始化 → 运行系统检查 → 启动。跳过初始化直接启动通常会被拦下来。

首次使用

  1. 打开 LuCI「服务 → Honk」，在概览页创建管理员账号（用户名 + 8 位以上密码）
  2. 点「运行系统检查」，看设备是否满足 eBPF / BTF / 模块 / 端口条件
  3. 确认无误后点「启动」，状态变成运行中
  4. 需要 Web 面板时点「打开 Doona」，它由核心直接提供，不另起服务

服务设置

项默认说明
LAN 网络lan接管哪个接口的流量
监听端口9527核心原生 API 的端口，只监听 LAN 地址
启用 Clash API关给 Zashboard 这类面板用，默认端口 9090
Clash API 密钥空启用时必填，6–128 位字母、数字、点、下划线或连字符

设置存在 /etc/config/honk，实际生效的配置在 /etc/honk/：

路径内容
/etc/honk/config.dae运行配置：节点、订阅、分组、路由、DNS
/etc/honk/system.dae面板托管的 global / experimental 段
/etc/honk/state/运行状态与缓存

谁在管这份配置

面板能不能改「服务设置」，取决于 config.dae 的写法：

写法面板行为
只有 include { system.dae }（可再带节点/分组等）面板可以改端口、LAN、Clash API，改动写进 system.dae
自己写了 global / experimental这些设置归你的文件，面板只读
两者都有面板不猜归属，显示一个「切换为面板管理」按钮，点了会先备份原文件再把这两段交给面板

切换前的弹窗会列出会变动和会保留的项，取消不会改动任何东西。

加节点与订阅

两条路，最终都落在 config.dae：

  • LuCI「配置」页：贴订阅链接或分享链接，支持 Clash YAML / Base64 / 纯链接列表；也可以直接导入已有的 dae 配置
  • 手写 config.dae：node { label: 'share-link' } 或 subscription { tag: 'url' }，重载后生效

路由、DNS 与订阅也可以只在 Doona 面板里管。面板改完会写回同一份配置，LuCI 侧刷新就能看到。

Geo 数据

路由用的 GeoIP / GeoSite 来自 v2ray-geoip / v2ray-geosite，与 daede 共用 /usr/share/v2ray。

  • 维护页可以手动更新，也可以开启自动更新（honk.main.geo_auto，频率 geo_auto_freq，默认 daily）
  • 也可以填自己的 GeoIP / GeoSite 下载地址
  • 更新失败不会删掉现有数据文件

维护页能做什么

  • 软件包更新（只查本机 apk 源，见升级）
  • Geo 数据：手动更新 / 自动更新 / 自定义下载地址
  • 配置备份与恢复：导出、导入、恢复到某个时间点
  • 系统检查：内核、BTF、模块、端口、冲突逐项检查
  • 重置：数据重置（先停服务）与管理员密码重置
