初始化与配置

装完包之后，服务默认是停的、也没初始化。顺序是：初始化 → 运行系统检查 → 启动。跳过初始化直接启动通常会被拦下来。

首次使用

  1. 打开 LuCI「服务 → Honk」，在概览页保存首次引导的 LAN、端口与 API 选项，再创建管理员账号（用户名 + 8 位以上密码）
  2. 点「运行系统检查」，看设备是否满足 eBPF / BTF / 模块 / 端口条件
  3. 确认无误后点「启动」，状态变成运行中
  4. 需要 Web 面板时点「打开 Doona」，它由核心直接提供，不另起服务

首次引导设置

这些选项只在安装默认配置上进行首次引导时使用。初始化后，在配置页直接修改 config.dae；手写配置不会被向导覆盖。

项默认说明
LAN 网络lan接管哪个接口的流量
监听端口9527核心原生 API 的端口，只监听 LAN 地址
启用 Clash API关给 Zashboard 这类面板用，默认端口 9090
Clash API 密钥空启用时必填，6–128 位字母、数字、点、下划线或连字符

设置存在 /etc/config/honk，这些选项不再持续生成运行字段，实际生效的配置在 /etc/honk/：

路径内容
/etc/honk/config.dae完整运行配置：global、experimental、节点、订阅、分组、路由和 DNS
/etc/honk/system.dae保留的旧布局文件；只有被主配置 include 时才生效
/etc/honk/state/运行状态与缓存

谁在管这份配置

config.dae 是运行配置的权威来源，启动、重启和修复不按 UCI 重建 global 或 experimental。UCI 继续保存服务状态、Geo 更新及首次引导意图。

升级不自动合并现有文件。仍使用规范 include { system.dae } 的配置，可在配置页点击合并预览，检查完整候选后确认应用。应用会启动服务；旧 system.dae 和已有草稿会保留，来源发生变化时必须重新预览。

含额外 include、重复系统块或其他无法确认的结构时，不自动合并，原布局仍可运行。配置页保留旧 system.dae 的编辑入口。恢复备份时保留文件里的接口与监听地址，换设备后需自行确认是否适用。

升级时保持原有配置

本次测试中，包管理器在一种情况下替换了 config.dae：装完包、完成首次引导、但从未启动过服务。此时旧主配置与包内默认文件字节完全相同，升级会被判为“未修改”而直接覆盖。其他已测状态（跑过启动、改过主配置、完整单文件）都保留了原文件。

honk 包用两个钩子处理这一种情况：升级前把旧 config.dae 与 system.dae 保存到 /etc/.honk-preupgrade/，升级后仅当以下条件全部成立时才原样写回：无 honk-core 进程、当前 config.dae 就是本包默认模板、system.dae 与保存时一致。写回后校验文件摘要与核心配置校验。

钩子不做任何服务启停，不改 /etc/config/honk，不合并配置。服务是否启动由 enabled 等现有状态与 default_postinst 决定；恢复失败也不会阻止后续默认的 start。写回前会把当前文件快照到同一事务目录，校验失败时从该快照回滚，并区分“已回滚”与“回滚失败”分别记日志。APK 上 pre-upgrade 失败不会中止安装（apk 3 的行为），这种情况下没有副本可写回，配置会保持被替换后的状态。

升级后状态库提示损坏

旧版本写下的状态库可能和新核心不兼容。升级后如果启动失败并提示 状态数据库损坏（RPC 返回 state_database_corrupt），说明核心拒绝了这个库，不是配置错误。

处理办法：到「维护」页执行重置。重置前会把旧库复制到 /etc/honk-pre-reset/honk.db.<时间戳>，需要取回订阅或排查时可以取用。重置会清空订阅、节点、策略与缓存，管理员账号需要重新创建。

插件不做自动迁移：库里是用户数据和凭据，静默清空等于静默丢数据，而且无法区分版本不兼容与真正的损坏（断电、磁盘错误）。这个提示只针对一次升级过渡，后续版本正常使用不会触发。

加节点与订阅

两条路，最终都落在 config.dae：

  • LuCI「配置」页：贴订阅链接或分享链接，支持 Clash YAML / Base64 / 纯链接列表；也可以直接导入已有的 dae 配置
  • 手写 config.dae：node { label: 'share-link' } 或 subscription { tag: 'url' }，重载后生效

机场校验 User-Agent 时，在订阅表单里填上它要求的 UA，预检和核心拉取会用同一个；留空则走核心默认的 honk/<版本>。更新间隔按天填，默认 1 天，填 0 关闭定时刷新。

路由、DNS 与订阅也可以只在 Doona 面板里管。面板改完会写回同一份配置，LuCI 侧刷新就能看到。

Geo 数据

路由用的 GeoIP / GeoSite 来自 v2ray-geoip / v2ray-geosite，与 daede 共用 /usr/share/v2ray。

  • 维护页可以手动更新，也可以开启自动更新（honk.main.geo_auto，频率 geo_auto_freq，默认 daily）
  • 也可以填自己的 GeoIP / GeoSite 下载地址
  • 更新失败不会删掉现有数据文件

日志

默认模板里 log_file 为空，核心日志只写 logread，由面板的日志页读取。

需要在重启后仍能翻查时，可以把 log_file 设成绝对路径或相对 data_dir 的文件名。写入位置在 overlay 上会持续增长，轮转行为取决于所用核心，配置前请先确认。

维护页能做什么

  • 软件包更新（只查本机 apk 源，见升级）
  • Geo 数据：手动更新 / 自动更新 / 自定义下载地址
  • 配置备份与恢复：导出、导入、恢复到某个时间点
  • 系统检查：内核、BTF、模块、端口、冲突逐项检查
  • 重置：数据重置（先停服务）与管理员密码重置
